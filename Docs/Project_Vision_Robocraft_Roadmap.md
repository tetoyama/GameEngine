## 1. 最終ゴール

Freejam『Robocraft』型の**キューブ&パーツ・ビルド&バトル**ゲームを、本自作エンジンで作り上げる。

- プレイヤーはグリッド上にブロックと機能パーツ(移動・武器)を組んでロボットを設計する
- 設計したロボットで、オンラインアリーナで撃ち合う
- 被弾でブロックが脱落し、接続が切れた部位は機能停止、コア破壊で撃破

Robocraft本家はFreejam閉鎖(2025-01)によりサーバー停止・削除済み。生きた参照は無い前提で、仕様は自分たちで定義する。

## 2. なぜ今の基盤作業がゴールへ直結するか

現行の基盤トラックは、Robocraft型に必要な技術と本質的に一致している。寄り道ではなく土台。

| ゲーム要件 | 対応する現行基盤 | 現状 |
|---|---|---|
| 大量キューブの描画 | Static Batching / Instancing (`System/Render/StaticBatch/`) | 大幅実装済 |
| ロボット=ブロックの集合体 | ECS(世代付きEntity / ComponentRef) | Step 1-12 完了 |
| 車体物理・重心・推進 | PhysX(Task分割済) | Step 15 実装済・実機確認待ち |
| ブロック破壊=接続グラフ切断 | ECS構造変更 + 並列Scheduler | 基盤あり |
| オンライン対戦 | Network(GN31 / Winsock) | 初期実装・堅牢化中 |
| 多数Entity/Systemの安全な並列 | Job System / Parallel Schedule Executor | Step 13-14 完了 |

## 4. 技術的に重い3層(重点注意)

基盤が整っても、以下のゲーム固有層が別途大きな実装コストとして残る。ここが勝負どころ。

1. **ビルドモードUX + 接続判定** — グリッドスナップ、連結性、対称、快適な操作感。地味だが体験の核。
2. **戦闘の物理ネットワーク同期(R5)** — 最難関。破壊を伴う物理は完全決定論が難しく、権威+補正の設計が要。
3. **破壊表現(R4)** — 接続グラフの動的更新、脱落パーツの見せ方、性能との両立。
